# Reader methods

The implementation originated in a local binary-format investigation of a user-provided Cameca 7f-GEO image file. The source data and original investigation are retained outside this repository. The observed constants and unresolved meanings are documented in `docs/format.md`; code has not been promoted to a scientifically validated reader.

The parser opened files read-only and read bounded metadata records through their absolute pointers. It derived the opaque header boundary from the earliest image pointer, replacing the original specimen-specific fixed boundary without changing the decoding hypothesis. It required exact acquisition-major, channel-minor block coverage, equal block sizes and acquisition counts across channels, and the observed structural markers. Unknown or inconsistent variants were rejected explicitly.

With explicit provisional acceptance, the reader interpreted each requested block as a square, C-order array of little-endian unsigned 16-bit values. The shape was inferred from block length rather than assigned from an unverified vendor field. No missing values were imputed, no zeros were treated as missing, and no pixels or acquisitions were excluded. No correction, normalization, filtering, registration, calibration, or scientific statistic was applied. Units and physical scale remained unknown. Read-only arrays preserve the decoded values independently of the file handle.

Files remained open for the duration of a reader context. Device, inode, byte size, modification time, and change time were checked around payload reads and full-source hashing to detect ordinary concurrent modifications. This is not an adversarial integrity guarantee. Optional SHA-256 hashing explicitly read the full source. Plane extraction recorded source and plane hashes, reader version, selected indices, and provisional assumptions in a JSON sidecar next to the NumPy array.

Routine verification used explicitly artificial binary files generated by `tests/fixtures.py`. Test dimensions, labels, padding, and sentinel values were chosen as test inputs and do not represent measured data. Tests covered layout relocation, numerical preservation, source changes, invalid inputs, and CLI behavior. The optional `scripts/verify_sample.py` comparison used the original local probe to compare every plane and the full source checksum. Agreement with that reference confirms regression fidelity only; independent vendor validation remains outstanding.

The package and its dependency groups are declared in `pyproject.toml` and locked in `uv.lock`. Commands to reproduce checks are in `README.md`. No stochastic analysis is performed. The source repository is public at https://github.com/bradleylab/sims-reader; private specimens and local comparison outputs are excluded.

## Zarr conversion

The converter writes local Zarr v3 stores with named acquisition-index, channel, row, and column dimensions. It streams one source plane at a time and preserves the provisional uint16 interpretation. Index coordinates and separate channel labels retain acquisition order and allow duplicate labels. Original header bytes are stored unchanged. Zstandard compression is lossless; its configuration and installed library versions are recorded with source and reader-code hashes. No analytical transformations or display pyramids are generated.

Verification reopens the staged store and compares every plane, coordinate, label, header byte, and root provenance record. It checks that all chunks exist, including all-zero chunks, so missing chunks cannot pass as valid zero data. The original array writer is retained because Zarr 3.3 does not preserve its runtime write-empty-chunks setting when reopening arrays. Source hashes before and after conversion must match. Tests also open output through xarray with masking enabled and disabled to check preservation of integer values and zeros.

Output is reserved exclusively and staged beneath the destination. Verified entries are promoted using local renames, with root metadata last; this is not a transaction across all files. The conversion subgroup carries the final completion receipt. Failed or interrupted destinations must not be treated as complete or reused automatically. See `docs/zarr.md`. A completed conversion establishes storage fidelity to this decoder, not independent validation of the instrument format.

Standalone verification uses the same plane and schema checks as conversion, recomputing source-derived metadata and comparing the completion receipt. It does not rewrite the source, store, or provenance. Relocated source and destination paths are allowed. Historical software identifiers are retained and structurally checked, not authenticated against the original runtime. Users must verify stores while they are not being modified; this is an integrity check, not an adversarial or transactional guarantee.

## Batch conversion

Batch discovery is deterministic and nonrecursive unless requested. It preserves relative directory structure and matches .im extensions case-insensitively. The destination plan checks normalized case-folded names and ancestor conflicts before writing. Existing outputs are failures, never implicit skips or resumed conversions. Every eligible file uses the same mandatory conversion verification. Per-file exceptions are recorded with their type and message while independent inputs continue. No pixels are aggregated across files and no scientific methods change. Ctrl-C during conversion records the interrupted and remaining unattempted files; forced termination cannot guarantee a final report. Input/output trees must be disjoint and not concurrently modified.
